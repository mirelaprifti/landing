Introducing Effect UI

Effect UI is the new frontend library that continues the work of Foldkit 0.x, the framework at foldkit.dev. We announced it as the "new frontend foundation" in Foldkit Joins Effect.

Effect UI is in public preview: it isn't on npm yet and doesn't have everything Foldkit 0.x has. If you're building with Foldkit 0.x today, we encourage you to continue. The migration to Effect UI will be an upgrade, not a rewrite. Feature work on Foldkit 0.x has moved to Effect UI.

This page is built with Effect UI. You can read its source on GitHub.

What this article covers

The building blocks of an Effect UI app: Components, how state and data flow through them, how views render, and how to test and debug the result. Each section compares the Effect UI version with Foldkit 0.x so you can see what changes when you migrate.

Components

A Component is the unit you build an Effect UI app from. It owns a model, handles messages, and renders a view. Larger Components are composed from smaller ones, and every message travels through the same typed path, so you can follow any change from the click that caused it to the pixels it produced.
